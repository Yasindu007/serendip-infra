# Plan: Spec 005 — K3s bootstrap

Status: Draft — awaiting human approval before implementation.

## Open-question resolutions

1. **Disposable test environment: clone the existing WSL Ubuntu distro
   via `wsl --export`/`--import`, not `wsl --install`.** Tried
   `wsl --install --distribution Ubuntu-24.04 --name serendip-k3s-test`
   first — it failed: `wsl --install`'s distro catalog fetch from
   `raw.githubusercontent.com` times out from this machine (a real,
   confirmed network constraint, not a guess). `wsl --export Ubuntu
   <tarfile>` + `wsl --import serendip-k3s-test <dir> <tarfile>` is a
   pure local filesystem operation with no network dependency, and
   conveniently clones the Go toolchain already set up in the
   persistent dev distro (no re-setup needed inside the disposable
   copy). Verified before writing this plan: no partial registration
   was left behind by the failed `--install` attempt (`wsl -l -v`
   confirmed clean). Torn down via `wsl --unregister
   serendip-k3s-test` after verification (T007) — the persistent
   `Ubuntu` distro is never touched by the actual K3s install/uninstall
   cycle.
2. **iptables-nftables detection: parse `iptables --version`'s output
   string.** The command prints e.g. `iptables v1.8.9 (nf_tables)` or
   `(legacy)` — a regex extracts the version and the parenthesized
   mode. Warn (not hard-fail) when mode is `nf_tables` AND version is in
   the documented risky range (1.8.0-1.8.4) — research confirmed this
   is a known, mitigable issue (bundled binary or `update-alternatives`
   switch), not a guaranteed failure, matching spec.md's "detect and
   warn, full remediation out of scope."

## Approach

**`agent/bootstrap`: pre-flight checks (parse-from-bytes, same pattern
as `agent/discover`), install/uninstall via `os/exec` shelling out to
K3s's official scripts (never reimplementing install logic — constitution
rule 10), and post-install polling verification.**

```go
// agent/bootstrap/preflight.go
func parseSystemdStatus(output []byte, cmdErr error) (ok bool, warning string, err error)
func parseIPTablesVersion(output []byte) (version, mode string, err error)
func checkLinux() error   // reuses runtime.GOOS, same as agent/discover
func checkRoot() error    // os.Geteuid() == 0
func checkSystemd() (warning string, err error)     // thin wrapper: runs `systemctl is-system-running`, calls parseSystemdStatus
func checkIPTablesMode() (warning string, err error) // thin wrapper: runs `iptables --version`, calls parseIPTablesVersion

// agent/bootstrap/install.go
type InstallOptions struct {
    Version string        // INSTALL_K3S_VERSION, e.g. "v1.36.4+k3s1"
}

const DefaultVersion = "v1.36.4+k3s1" // current K3s stable channel as of this spec (oss-researcher, 2026-09-26)

// InstallEnv returns the exact env vars Install would set -- the single
// source of truth both --dry-run and the real Install path read from,
// so there's no way for the printed dry-run command to drift from what
// actually runs.
func InstallEnv(opts InstallOptions) []string

// Install downloads the official get.k3s.io script via net/http and
// pipes it to `sh -s -` with InstallEnv(opts) set -- not a shell
// pipeline string (`curl | sh`), so there's no shell-quoting ambiguity
// and download/exec errors are distinguishable.
func Install(ctx context.Context, opts InstallOptions) error

// agent/bootstrap/verify.go
func WaitForReady(ctx context.Context, timeout time.Duration) error
// polls `systemctl is-active k3s` then `k3s kubectl get nodes` Ready
// condition, sleeping between attempts; returns a clear timeout error,
// never blocks past the given timeout.

// agent/bootstrap/uninstall.go
const uninstallScriptPath = "/usr/local/bin/k3s-uninstall.sh" // official, auto-generated by Install
func Uninstall(ctx context.Context) error
```

**`cmd/serendip-agent`'s new `bootstrap` subcommand**:

```
serendip-agent bootstrap --dry-run
    Prints the exact env vars and script source Install would use.
    No root required, no host mutation, always safe -- works even
    without --confirm (this IS the safe-inspection path).

serendip-agent bootstrap --confirm [--version=v1.36.4+k3s1] [--timeout=5m]
    Pre-flight checks (checkLinux, checkRoot, checkSystemd hard-fail;
    checkIPTablesMode warns) -> Install -> WaitForReady. Refuses to run
    without --confirm (agent/CLAUDE.md's hard rule), printing the same
    dry-run summary and exiting non-zero instead.

serendip-agent bootstrap --uninstall --confirm
    checkLinux, checkRoot -> Uninstall. Also refuses without --confirm.
```

Mirrors `discover`/`register`'s stdlib `flag.NewFlagSet` pattern — no
new CLI framework dependency.

## Risks

- **This is the riskiest spec so far: real root-level host mutation,
  not reversible by a Go-level rollback** (only by the official
  uninstall script, itself a real host mutation). Mitigated by: never
  testing against the persistent dev WSL distro (open-question
  resolution 1), `--dry-run` as a no-privilege inspection path, and
  `--confirm` required for both install and uninstall.
- **Downloading and piping a remote script to `sh` is an inherent
  supply-chain trust point** — mitigated by using K3s's *official*
  install path exactly as documented (which itself checksums the binary
  it downloads) rather than a custom implementation, and by explicit
  version pinning so what installs today is reproducible, not whatever
  "stable channel" resolves to when re-run later.
- **Swapping Flannel for Cilium later likely means a fresh cluster, not
  a live migration** (spec.md Scope-OUT) — a real cost of leaving K3s's
  defaults enabled now, worth remembering when Cilium's own provider
  spec is planned, not something to solve here.
- **`k3s kubectl get nodes` Ready-condition polling has a known timing
  gotcha** (oss-researcher: the API server may not exist yet
  immediately after the install script exits) — `WaitForReady` must
  tolerate early "no matching resources"/connection-refused errors as
  "not ready yet," not surface them as fatal, until the timeout is
  actually reached.

## Explicitly NOT done in this spec

- Recommended-profile computation / topology planner.
- Multi-node join/enrollment.
- Disabling K3s's bundled Traefik/ServiceLB/local-storage/Flannel.
- Embedded etcd / HA.
- Installing `serendipd` onto the bootstrapped node.
- Non-Linux support.
- Any `api/`/`core/` change.
